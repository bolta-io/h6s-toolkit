# 공통 룰북 — internal-finance

전 시나리오가 공유하는 환경변수, 계정과목 분류, 거래처명 변형 매칭, 금액·날짜 허용오차 규약.

## 환경변수 규약

| 변수 | 누가 사용 | 없을 때 동작 |
|---|---|---|
| `H6S_API_KEY` | 모든 시나리오 (CLI 가 자동 읽음) | CLI 가 `NO_API_KEY` → `h6s init` 안내 |
| `SLACK_WEBHOOK_URL` | A1, A3, B1, B2, B3 | stdout fallback + 사용자 보고 |
| `SLACK_WEBHOOK_URL_DUNNING` | A3 (DM 채널 분리 시) | `SLACK_WEBHOOK_URL` 로 fallback |
| `NOTION_TOKEN` | A2, A3, A4 | stdout fallback |
| `NOTION_DB_RECONCILE_SALES` | A2 | A2 미매칭은 CSV 만 저장 |
| `NOTION_DB_DUNNING` | A3 | A3 미수금 트래커는 CSV 만 |
| `NOTION_DB_RECONCILE_PURCHASE` | A4 | A4 미매칭은 CSV 만 |
| `INTERNAL_FINANCE_OUTPUT_DIR` | 전 시나리오 CSV 저장 경로 | `./out/` 기본 |

## 계정과목 분류 룰북 (분개 제안용)

A1 daily-bank-summary 가 거래 적요·금액·상대계좌를 보고 계정과목을 제안할 때 따르는 룰. AI 추론 전에 룰북을 먼저 적용하고, 매칭이 없을 때 AI 가 자유롭게 제안한다.

### 입금 (자산 증가)

| 적요 패턴 | 제안 계정과목 | 근거 |
|---|---|---|
| `*입금*` + 거래처명 (팀 거래처 DB) | 매출채권 회수 | 거래처 등록되어 있음 |
| `이자`, `예금이자` | 이자수익 | |
| `법인세 환급`, `부가세 환급` | 미수환급세금 | |
| `급여` + 인명 (반환) | 가지급금 회수 | |
| 그 외 | AI 추론 또는 "미분류" | |

### 출금 (비용/지출)

| 적요 패턴 | 제안 계정과목 | 근거 |
|---|---|---|
| `*급여*`, `*월급*` | 급여 (판관비) | |
| `*4대보험*`, `국민연금`, `건강보험`, `고용보험`, `산재보험` | 복리후생비 / 예수금 차감 | |
| `*법인세*` 출금 | 법인세비용 | |
| `*부가세*` 납부 출금 | 부가세예수금 차감 | |
| `*임대료*`, `*월세*` | 지급임차료 | |
| `*전기료*`, `*가스*`, `*수도*` | 수도광열비 | |
| `*카드결제*` | 미지급금 (카드매입금 차감) | |
| `*세무*`, `*회계*`, `*법무*` 서비스 | 지급수수료 | |
| `*광고*`, `*마케팅*`, 광고 플랫폼명 | 광고선전비 | |
| `*SaaS*`, `*구독*`, `AWS`, `Google`, `Notion`, `Slack` 등 | 지급수수료 (소프트웨어) | |
| 직원 인명 송금 | 가지급금 | 인명-사번 매칭 필요 |
| 그 외 | AI 추론 또는 "미분류" | |

### 팀 거래처 DB

팀 거래처 명단은 환경변수 `INTERNAL_VENDOR_LIST_PATH` (CSV 파일 경로) 에서 로드. 형식:

```csv
biznum,vendor_name,nickname,default_account
123-45-67890,(주)예시거래처,예시,매출채권
...
```

CSV 가 없으면 거래처명 매칭은 AI 추론에만 의존.

## 거래처명 변형 매칭

세금계산서 공급자명/입출금내역 상대계좌명이 자주 다르다. 매칭 시 다음 변형을 모두 시도:

1. **법인 접두/접미사 제거**: `(주)`, `㈜`, `주식회사`, `유한회사`, `(유)`, `(합자)` 제거 후 비교
2. **공백·점·괄호 제거**: `에이비씨 ㈜` ↔ `에이비씨주식회사` ↔ `에이비씨(주)`
3. **영문·한글 혼용**: `Example Corp.` ↔ `예시상사`
4. **약어**: 환경변수 `VENDOR_ALIAS_PATH` 의 CSV (`alias,canonical`) 에서 룩업
5. AI fallback: 위 4단계가 모두 미스이면 AI 에게 두 이름이 같은 거래처인지 confidence 0~1 로 판정 요청 → ≥ 0.8 만 매칭으로 인정

## 금액·날짜 허용오차

대사 시나리오(A2, A4) 가 매칭 가능으로 판정하는 기준:

| 항목 | 허용오차 | 비고 |
|---|---|---|
| 금액 | 0원 (정확히 일치) | 수수료가 의심되면 ±10원 |
| 날짜 | ±3 영업일 | 발행일 ↔ 입금일 |
| 발행일 ↔ 만기일 | 룰 없음 | 만기일은 정보용 |

허용오차 범위 밖이면 "후보(낮은 신뢰도)" 로 표시하고 사람 검토로 넘긴다.

## 금액·통화 표기

- 모든 금액은 원 단위 `BigDecimal` (소수점 없음). 출력 시 `Intl.NumberFormat('ko-KR')` 또는 `numfmt --grouping` 으로 천 단위 콤마.
- 외화 거래는 통화코드(`currencyCode`) 별도 표기.

## 회계 기간 표기

- 월: `2026-04` (ISO 8601 month)
- 분기: `2026-Q2` (관례 약식)
- 회계연도: 1월 1일 ~ 12월 31일 (팀 정책 — 변경 시 이 룰북 갱신)

## 출력 라우팅 우선순위

같은 시나리오에서 여러 출력처가 활성화되면 순서:

1. **CSV 파일** — 항상 먼저 저장 (감사용)
2. **Notion** — 누적 트래커 (다음 회차에서 비교)
3. **Slack** — 사람에게 알림 (CSV/Notion 링크 포함)

Slack 메시지에는 CSV 파일 경로와 Notion 페이지 URL 을 둘 다 인용.
