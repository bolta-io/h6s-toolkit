# 공통 룰북 — mcp-finance

전 시나리오가 공유하는 **자연어 ↔ tool 호출 매핑** 규약. 클라이언트가 사용자 자연어를 받아 어떤 tool 을 어떤 인자로 호출할지 결정할 때 따른다.

## 기간 해석

자연어 표현 → 절대 날짜 변환은 다음 우선순위로 처리. 모호하면 사용자에게 한 번 묻는다.

| 자연어 | 해석 | 비고 |
|---|---|---|
| `이번주` | 월요일 00:00 ~ 오늘 (조회 시점) | 한국 주 단위(월~일) |
| `지난주` | 직전 월요일 ~ 직전 일요일 | |
| `이번달` | 1일 ~ 오늘 | `month=YYYY-MM` 인자로 호출 가능 (CLI 와 동등) |
| `지난달` | 직전 1일 ~ 말일 | 가장 자주 쓰는 단위 — `month` 직접 지정 |
| `Q1 / 2026-Q1` | 1월 1일 ~ 3월 31일 | 분기 부가세 시나리오 기본 |
| `지난 분기` | 직전 분기 첫날 ~ 말일 | 신고 시즌 자주 사용 |
| `최근 30일` | 오늘 -30일 ~ 오늘 | schema `maxRangeDays` 초과 주의 |
| 명시 없음 | 직전 1개월 | 기본값. 사용자에게 "지난 한 달 기준으로 답합니다" 한 줄 명시 |

`h6s_fetch_data` 의 `month` 가 있으면 `dateRangeStart/End` 보다 우선. 분기·주 단위는 `dateRangeStart/End` 사용.

## schema 추론

자연어 → schema 매핑. 한국어 의도는 다양해도 결국 6개 ContractRecord 중 하나로 모인다.

| 자연어 의도 | schema |
|---|---|
| 은행 입출금내역 / 자금 흐름 / 거래 내역 | `bank.transactions.cb.v1` |
| 잔액 / 계좌 정보 | `bank.accounts.cb.v1` |
| 매출 세금계산서 / 발행한 계산서 | `hometax.tax-invoices.sales.v1` |
| 매입 세금계산서 / 수취한 계산서 | `hometax.tax-invoices.purchase.v1` |
| 매출 현금영수증 / 발행 현금영수증 | `hometax.cash-receipts.sales.v1` |
| 매입 현금영수증 / 수취 현금영수증 | `hometax.cash-receipts.purchase.v1` |

부가세·종소세 시나리오는 4종 동시(매출/매입 세금계산서 + 매출/매입 현금영수증) — 병렬 호출.

## 응답 요약 포맷

기본 3줄을 사용합니다. 자세한 row는 사용자가 추가 요청할 때만 보여줍니다.

```text
✓ <시점/대상> <핵심 수치 1~2개>
<분해 또는 비교 1줄 — 입금/출금 합, 매출/매입 합 등>
<후속 한 줄 — 콘솔 링크 또는 "○○도 보여드릴까요" 자연어 권유>
```

- 한국어 숫자 포맷: `1,540,000` (3자리 콤마)
- 통화 단위: 명시하지 않음 — `원` 은 한 번만 (그리고 가급적 응답 끝에서 한 번)
- 시간대: 한국 KST 기준 (`2026-04-29 10:30`)

## 자동 제보 룰 (`h6s_report_bug`)

다음 경우 사용자에게 묻지 말고 즉시 `h6s_report_bug` 호출:

- 같은 schema/기간으로 fetch 시 응답 `errorCode` 가 동일하게 2회 이상
- 응답 row 수가 0인데 사용자가 "있어야 한다" 고 명시한 경우
- `h6s_fetch_data` 응답에 `httpStatus >= 500` 또는 `errorCode` 가 정의되지 않은 unknown 코드
- 응답 형태가 schema 정의(`h6s_get_schema` 결과) 와 어긋남 (필수 필드 누락 등)

severity 기준:

| 신호 | severity |
|---|---|
| 데이터 누락 의심 | MEDIUM |
| 응답 형태 어긋남 / unknown errorCode | HIGH |
| 5xx / 백엔드 장애 | HIGH |
| 인증/권한 일관 실패 | MEDIUM (사용자 책임 가능성) |

`title` 은 한 줄 한국어, `description` 에 요청 endpoint / 응답 errorCode / 재현 절차 (사용자 자연어 한 줄 포함).

## 사용자에게 묻기 전 추론 우선순위

채팅에서 다시 묻는 빈도를 줄이는 것이 사용자 경험의 핵심. 다음 우선순위로 자동 추론을 시도하고, 마지막에만 사용자에게 한 줄 질문.

1. **자격증명 1개** → 자동 선택
2. **provider 명시 + 자격증명 매칭** → 자동 선택
3. **자연어에서 기간 추출 가능** → 기본값으로 사용하고 응답에 명시 ("지난 한 달 기준")
4. **schema 의도 명확** (예: "입출금내역") → 단일 schema 자동 결정
5. **여러 후보** (예: 다중 은행 자격증명 + provider 안 적힘) → 한 줄 질문 ("어느 은행이요?")

질문은 한 번에 한 가지만. 두 가지 이상 모호하면 우선순위 높은 것부터 1개씩.
